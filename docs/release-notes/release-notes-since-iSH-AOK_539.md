# Release Notes Since `builds/iSH-AOK_538`

These notes summarize changes from `builds/iSH-AOK_538` intended for `builds/iSH-AOK_540`. (Build 539 was never tagged/released — App Store Connect rejected the archive over a disallowed entitlement before it shipped; see Maintainer Notes.)

This is a large cycle. The headline is a new **Workspace "Wayland" applet**: a headless Wayland desktop (labwc or sway, `foot` terminal, `wayvnc`) running inside the guest and rendered natively in-app through a hand-rolled RFB client, replacing an earlier WKWebView/noVNC prototype — plus a new **Workspace file manager and viewer suite** (Finder-style File Manager, Markdown Reader, Image Viewer, Video Player). Both landed over long sequences of commits that also fixed real device-found crashes and hangs along the way. Also in this range: **Apple Foundation Models is now a real, on-device LLM Chat backend** (not a stub) with conversation memory and Shell Tools; a rebuilt chat-bubble transcript UI; three separate signal-delivery/locking bugs that could permanently wedge a multithreaded guest process (SIGCHLD missed-wakeup, a sighand/poll AB-BA deadlock, and a tgroup signal-queue gap); a fakefs metadata/host-filesystem TOCTOU race; two arm64 JIT correctness bugs that crashed `nvim`; an iovec ABI marshaling bug that corrupted `strace -f` output on arm64/riscv64; two `fs/sock.c` bugs around lost socket errors; a riscv64 CSR fix needed by Go binaries; two 64-bit-guest correctness fixes (amd64 `preadv2`/`pwritev2`, ABI-aware crash dumps); and a bind-conflict fix carried over from the prior cycle's in-progress work.

## Highlights

- **Workspace: a native "Wayland" Display applet.** Runs a headless Wayland compositor (labwc by default, sway as an alternative) plus `foot` and `wayvnc` inside the guest, rendered through a hand-rolled RFB 3.8 client and an MTKView (Metal) — no WebView, no vendored noVNC. Supports pointer/keyboard/clipboard input (including hardware-keyboard Alt combos for the compositor's own bindings), a themed labwc menu/keybindings matching the app's own palette, and a generated Applications pipemenu that lists whatever's installed. Device-verified end-to-end: connects, renders a live desktop, and runs real GTK4 apps (forced to software rendering — no GPU/DRM in this environment).
- **Apple Foundation Models is now a real LLM Chat backend.** The prior "not available in this build" stub is gone — Xcode 26.6's iOS 26.5 SDK ships the framework. Gets conversation memory (each reply used to see only the latest prompt), Shell Tools support (the same guest-command-execution loop the OpenAI-compatible backend already had), and a broader guest-environment probe (init system, package manager) so the model doesn't have to discover `systemctl` doesn't exist by trial and error.
- **LLM Chat transcript rebuilt as per-message bubbles**, replacing a single scrolling text view: independently-scrolling code blocks with a Copy button and language tag, selectable prose text, a Stop button that can cancel any in-flight backend (including a raw-socket SSE stream or an Apple FM `Task`), and a hardened Clear that actually starts a fresh session.
- **Workspace: File Manager, Markdown Reader, Image Viewer, and Video Player applets.** A Finder-style file manager (sidebar, breadcrumb navigation, sort/hidden-files/new-folder, row context menu, swipe-to-delete, hardware-keyboard shortcuts) opens files by extension into a non-editable Markdown reader (with pipe-table rendering), a pinch-zoomable Image Viewer, or an AVKit-backed Video Player, all sharing a new `GuestFileBridge`. All four are wired into the Modern Launcher's "Add Built-in" list, persist their open file/directory across app restarts, and picked up a "Home" sidebar row and text-contrast fix this cycle.
- **Three signal-delivery/locking bugs fixed that could permanently wedge a multithreaded guest process** — found chasing a real Workspace Display-applet hang (labwc spawning app processes in bursts): a SIGCHLD missed-wakeup race, a `sighand->lock`/`poll->lock` AB-BA deadlock between signal delivery and `epoll_wait`, and a tgroup signal-queue gap that meant process-directed signals like SIGCHLD were invisible to every thread but the one that happened to receive them.
- **A fakefs TOCTOU race fixed**: concurrent `open(O_CREAT)`/`unlink`/`mkdir`/`rename` on the same path could leave the real host filesystem entry and SQLite metadata disagreeing about a file's type — the same mismatch that used to assert-crash `opendir()` on any command that hit it (`ls -la`, `rm -rf`, …), now also fixed at that crash site directly as defense in depth.
- **Two arm64 JIT bugs fixed that crashed `nvim` on launch**: a missing SIMD/FP literal-load gadget (any FP constant load SIGILL'd), and a logical-immediate (AND/ORR/EOR) instruction silently discarding writes to SP instead of targeting it, corrupting LuaJIT's own bytecode-PC register after a stack realignment. `nvim` went from crashing on most launches to 15/15 clean runs.
- **`strace -f`'s output on arm64/riscv64 guests was mostly garbage** — an iovec ABI marshaling bug (readv/writev/preadv/pwritev/`process_vm_readv`) used the 32-bit i386 struct layout on these 64-bit guests, corrupting every path/struct/array argument while leaving return values correct. Fixed.
- **Two `fs/sock.c` bugs**: a refused nonblocking `connect()` could falsely report success (a lost, one-shot `SO_ERROR` read consumed by an internal readiness probe) — hit in a live ssh-session investigation; and the `ENOTCONN`→`ECONNRESET` fixup for iOS backgrounding socket kills was missing from `recvmsg`/`recvfrom`/`sendmsg`/`sendto`, only ever applied to plain `read`/`write` — this made `chronyd` spin at ~50-65% CPU on the device after every background/foreground cycle.
- **riscv64: `rdtime`/`rdcycle`/`rdinstret` CSR reads implemented.** Go binaries call `runtime.nanotime()` via `csrrs rd, time, x0`, which the riscv64 CSR decoder didn't recognize (it only handled the FP CSRs) — any Go binary SIGILL'd on its first clock read.
- **amd64 `preadv2`/`pwritev2` (syscalls 327/328) implemented**, and **crash dumps are now ABI-aware** (`dump_stack()`/`dump_mem()` previously read the i386-only register fields unconditionally, printing garbage on amd64/arm64/riscv64).
- **A real bind-conflict bug fixed**: restarting a listening service could silently lose one address family if any client was still connected to it (an Apple-only preemptive `EADDRINUSE` check didn't distinguish a genuine listener from a plain established connection).
- **A deadlock fixed between `/proc` readers and an exiting task**, found chasing a device report of `foot` and `ktop` both segfaulting on corrupted pointers during a Wayland session's app-launch burst. `/proc/meminfo` and `/proc/net/tcp`/`udp` could permanently hang if a task started exiting while they were mid-scan — confirmed with a local repro (concurrent `ktop -b` instances against a continuous fork/exec churn loop) that hung indefinitely before the fix and now completes in ~1.2s. A companion fix backs off `do_exit`'s own poll interval under contention, turning what was previously a CPU-burning livelock (~280% CPU) into an efficient wait (~3% CPU) even before the deadlock itself is hit.

## User-Facing Changes

### Workspace: Wayland Display applet (new)

- Backend: `opt/AOK/tools/setup-wayland.sh` installs labwc (default) and sway (alternative, `WAYLAND_COMPOSITOR_CMD=sway`), plus `wofi`, `foot`, `wayvnc`, and a best-effort set of menu-filler apps (htop, btop, mc, neovim, vim) so the Applications menu isn't empty on a fresh rootfs. `start-wayland.sh` launches the stack and writes a readiness file the app polls, torn down on pty hangup (`fb5b30fb`, `2c7e6aa7`).
- Rendering went through two iterations: an initial WKWebView + vendored noVNC + WebSocket-to-TCP bridge (`fb5b30fb`, made to actually connect and render on-device with several fixes for WKWebView CORS/module-loading, Network.framework loopback scoping, and wayvnc readiness races — `845c1445`), then **replaced entirely** with a hand-rolled RFB 3.8 client (`DisplayRFBClient`) and an MTKView/Metal renderer, dropping the WebView/noVNC/bridge/static-file-server stack (`6b57294a`).
- Input: pointer, hardware keyboard, and a bidirectional clipboard bridge (guest→iOS automatic via RFB `ServerCutText`; iOS→guest via a toolbar Paste button, `e3818e1f`). Alt/Alt+Shift/Alt+Return are forwarded as their own key commands (Control stays free for in-terminal Ctrl combos) to drive sway's `$mod`/labwc's Alt-based keybindings.
- GTK4 apps (e.g. gnome-calculator) are forced to software rendering (`GSK_RENDERER=cairo`, `LIBGL_ALWAYS_SOFTWARE=1`) — there's no GPU/DRM device in this environment, and GTK4's default GL/Vulkan renderer crashed outright (`a0f818cc`).
- Device-found fixes to `start-wayland.sh`, all confirmed on-device: `su - <user> -c` doesn't fully reset `HOME`/`SHELL` for the target account, so the script now looks up the running uid's own `/etc/passwd` entry directly and prefers `/bin/bash` over a possibly-stale shell field; sway can name its Wayland socket anything (`wayland-1`, not just `wayland-0`), so socket discovery now globs for whatever appears; a `cmd | tee &` pipeline put `tee`'s pid, not the real process's, into `$!`, so cleanup was killing the wrong process — routed through named FIFOs instead; stale-process cleanup now kills both compositors by name in case a session switched which one it uses; labwc's Applications pipemenu now runs `Terminal=true` `.desktop` entries (btop, htop, neovim, mc) inside `foot` instead of silently doing nothing, and its per-`.desktop`-file `awk` invocations were collapsed to one process total to stay comfortably inside labwc's 4-second pipemenu timeout; labwc also gets a themerc matching the app's own Workspace palette and an rc.xml with Alt-based keybindings mirroring the right-click menu.
- The applet is labeled "Wayland" in the Workspace UI (was "Display", matching what it actually shows).
- Fixed: `/dev/shm` didn't exist on every bundled root (wlroots' shm keymap/buffer allocation has no fallback for a missing one) — now created unconditionally at boot, both in the app and the CLI harness (`0c035fd8`).
- New UI tests drive the real Utils/Workspace-menu → Display navigation path and assert the applet reaches "Connected" with a live desktop rendered (`300f0e72`, `45a28565`, `845c1445`).

### LLM Chat

- Apple Foundation Models is now a real backend (previously a stub reporting unavailability) — `AOKFoundationModelsBridge` wraps `SystemLanguageModel`/`LanguageModelSession`, weak-linked on iOS 26+ (`92776b45`).
- Shell Tools (guest command execution, with the same confirmation dialog and guest-environment probe the OpenAI-compatible backend uses) now work on the Apple FM backend too (`cc3eabf2`), and the probe itself is broader — actual init system (OpenRC/sysvinit, never systemd) and package manager (apk/apt), plus more detected tools (`4395660e`).
- Apple FM gained conversation memory: every reply used to start a brand-new session seeing only the latest prompt; prior turns are now flattened into the prompt (budget-capped so a long chat doesn't overflow FM's small context window) (`9820fd55`). Two follow-up fixes: a stale shell-tool handler from a previously-closed chat window could silently swallow later tool calls (`d07bcd96`), and FM has been observed invoking a tool more than once for a single logical call — repeat invocations with the same command text no longer re-prompt for approval (`d07bcd96`).
- Transcript rebuilt as a table view of per-message bubble cells instead of one scrolling text view (`4cb941e9`): fenced code blocks get their own horizontally-scrolling view with a language tag and per-block Copy button; long-press copies a whole message; a Stop button (replacing Send mid-reply) cancels whichever backend is active, including shutting down a raw-socket SSE stream's blocking `recv()` or cancelling an Apple FM `Task`. Fixed a crash opening chat history with any assistant reply already present (a `nil` inserted into a dictionary literal) (`06e8d16d`), and prose text is now a selectable (non-editable) text view instead of a plain label that couldn't be text-selected at all — the whole-bubble long-press-copy affordance was dropped in favor of normal iOS text selection (`5907fbf1`).
- Prompt input is now a multi-line, word-wrapping, auto-growing text view (Return inserts a newline; only Send submits), and Clear now actually starts a fresh session — cancels whatever backend call is in flight and drops the per-chat tool-approval cache and guest-environment probe cache along with the messages (`f24fc924`).

### Workspace: file manager and viewers

- **"Home" sidebar row**, resolved from the same `/etc/passwd` UID-1000 lookup described below (falls back to hiding the row if no such account exists), and guest paths used in generated shell commands are now shell-quoted (paths can contain spaces/metacharacters) (`a4d5c90a`).
- (Carried in from the prior cycle, included here for completeness: `GuestFileBridge`, the Finder-style File Manager, Markdown Reader, Image Viewer, and Video Player applets, an adversarial-review pass that fixed several open-on-launch crashes/a FIFO-open deadlock/a persist-path escape, and a text-contrast fix — all already documented in this file's history from before the version bump.)

### "Open Everything as Default User"

- No longer provisions its own account. The toggle used to create and maintain a separate "user" account in `/etc/passwd`/`/etc/group`/`/etc/shadow` on every boot so it worked even on a rootfs that never shipped one — in practice this meant a second, iSH-owned account whose fields (e.g. its shell, hardcoded to `/bin/sh`) permanently diverged from the rootfs's own conventions. It now looks up whatever account actually has UID 1000 (the conventional "first regular user" on Debian/Devuan/Alpine) at each use (`+[AppDelegate defaultUserAccountName]`), falling back to the unmodified root login if the rootfs has none. A rootfs that already ships a UID-1000 user is now targeted correctly for the first time (`a4d5c90a`).

### Filesystem

- **Fixed a TOCTOU race between fakefs mutators, `open(O_CREAT)`, and `stat()`**: concurrent `open(O_CREAT)`/`unlink`/`mkdir`/`rename` on one path could leave the real host filesystem entry and SQLite's `ish_stat` metadata disagreeing about the entry's type. Fixed by taking `inodes_lock` around the real-op+metadata pair in `fs/generic.c`'s mutators and in `generic_statat`, and reordering `fakefs_open` to take its metadata transaction before the real create. A self-deadlock the locking change introduced (`generic_unlinkat`/`rmdirat` calling back into `inode_check_orphaned`, itself taking the same lock) was fixed with an `_unlocked` variant for callers that already hold it (`81e58b65`).
- `realfs_opendir` no longer asserts (crashing the whole process) when `fdopendir()` legitimately fails because a path's on-disk state is inconsistent (recorded as a directory in metadata but backed by something else on the host, e.g. left by an install race) — returns the mapped errno instead (`15ff5d8e`).
- `/AOK/persist` and `/AOK/roots` are real host directories always owned, at the host layer, by the app's own uid — so iSH's normal owner-vs-other permission model could never see a non-default guest uid as "owner" there and fell back to non-writable "other" bits. New nodes created under these mounts are now forced world-writable, matching the intent that every guest uid can use them (`e113fa0f`).
- `main` (CLI harness): `/AOK` was silently never mounted at all when `ish` was launched from outside the repo root, because the gating check used a CWD-relative path; now resolved against the source tree's absolute path regardless of invocation directory (`96b1ec25`).

### Signals / locking

- **SIGCHLD missed-wakeup burst-spawn wedge fixed** — three layered bugs found via iterative live-process sampling of a real device hang (Workspace Display applet spawning several app processes in a burst): (1) a standard signal already pending correctly skipped re-queuing, but also skipped the wake attempt, silently dropping a second child's SIGCHLD if it raced the first's consumption; (2) fixing that exposed a latent hazard in `signal_wake_task`'s manual lock/unlock dance around `sighand->lock`, now given its own dedicated lock so two concurrent deliveries can't race it; (3) `is_signal_pending()` (which `sigsuspend`'s retry loop depends on) checked only the task's own pending set, never the shared `sighand->pending` set that a process-directed signal like SIGCHLD actually lands in. Verified via git-worktree A/B: unfixed hangs 25-57% of the time on a synchronized fork/exit burst; fixed, 240/240 trials clean (`1d402799`).
- **`sighand->lock`/`poll->lock` AB-BA deadlock fixed**: signal delivery to a signalfd took `sighand->lock` then (via `poll_wakeup`) `poll->lock`, while a concurrent `epoll_wait` scan on another thread of the same process took `poll->lock` then `sighand->lock` — opposite orders, permanently deadlocking two threads of the same multithreaded process (found via an on-device backtrace of a labwc Wayland session). Fixed with a non-blocking `poll_wakeup_trylock()` used from signal delivery's signalfd wakeup path; a skipped notify only adds latency, since the target task is independently woken via SIGUSR1 and readiness is re-checked on the next scan (`d128c721`).
- **Signal queue now shared across a tgroup's threads**: SIGCHLD (and other process-directed signals) was delivered only into the parent task's own per-task queue, so a signalfd/`sigpending` call on any *other* thread of a multithreaded process could never observe it — even though the wakeup mechanism itself correctly reached the shared poll structures. Now delivered once into a shared per-sighand queue; `signalfd_poll`, `receive_signals`, and `sigpending` drain both queues (`afd15cb5`), and a follow-up widened every other "does this thread have a deliverable signal" check (blocking-I/O EINTR paths in `fs/real.c`/`fs/sock.c`, `futex_wait`, ptrace's stop poll, the lockless fast path, task teardown) to also check the shared queue (`465417b5`).
- **`util/timer.c`: fixed an AB-BA lock inversion** between `timer->lock` and a callback's own locks (e.g. a timerfd's `fd->lock`, taken in the opposite order on the arming side) — the timer thread now drops `timer->lock` across the callback and re-takes it after, re-checking the generation to still discard a stale-generation wakeup raced by a concurrent arm/cancel.
- **`/proc` readers could deadlock against a task that starts exiting mid-scan.** `/proc/meminfo`'s `collect_mem_page_stats()` and the `/proc/net/tcp`/`udp` socket enumeration each snapshot the live task list, then blocking-`lock()` each task's `general_lock` in turn. `task_snapshot_collect()` only checks `task->exiting` once, at snapshot time — a task can start exiting afterward, while the snapshot loop is still working through the rest of the list. When that happens, `do_exit()` locks `general_lock` and waits for its reference count to clear, but the snapshot's own reference (held until the whole loop finishes) is exactly what keeps that count elevated — a genuine circular deadlock, not just contention. Found chasing a device report of `foot` and `ktop` both segfaulting on corrupted pointers during a Wayland session's app-launch burst: a local repro (`ktop -b` running concurrently with a continuous fork/exec churn loop) hung indefinitely. Fixed with the same trylock-and-skip pattern `proc_entry_stat()` already used for this exact race — a task that can't be locked immediately is mid-exit and about to disappear, so skipping its contribution to the snapshot is harmless. A companion fix gives `do_exit`'s own exit-wait poll an exponential backoff (was a fixed 2µs `nanosleep`, a syscall storm under heavy concurrent exits — a live sample of the stuck repro showed `do_exit`/`nanosleep` as the hottest frames, ~280% CPU); this alone doesn't fix the deadlock but turns it from a CPU-burning livelock into an efficiently-waiting one, which is what made it possible to sample and diagnose in the first place. Doesn't, on its own, explain the exact corrupted-pointer crashes seen on device — that needs a live device repro to pin down — but removes a confirmed, reproducible deadlock in the same /proc-scanning-under-load scenario that produced them (`c220ef9e`, `c0ccaed3`).
- **`concurrent_exec_tlb`'s long-standing local `waitpid: Interrupted system call` failure fixed** — a real bug, not a test artifact. `send_signal_to_group` (used to deliver SIGCHLD from an exiting child to its parent's thread group) queued and woke unconditionally, unlike the single-task delivery path, which correctly drops a group-default-ignored signal with no handler installed unless something is synchronously waiting for it. A burst of concurrently exiting children each unconditionally queued SIGCHLD into the parent's `sighand->pending` even with no `SIGCHLD` handler installed, so `wait_for()`'s EINTR check (used by `wait4`/futex/poll) reported `EINTR` to a `waitpid()` that was actually waiting on a different, still-live child. Now mirrors real Linux's `sig_ignored()` behavior across the whole group before touching `sighand->pending` at all. Also adds an EINTR-retry loop to the test itself, matching every other test in the suite, as defense in depth (`7103aebc`).

### JIT / CPU emulation

- **arm64: two bugs fixed that crashed `nvim` on launch.** (1) The JIT never implemented the SIMD/FP form of `LDR (literal)` (loading a float/double constant from a nearby literal pool) — any such instruction SIGILL'd; root-caused via live `gdb` on-device, LuaJIT hits this within milliseconds of startup (`41b8a008`). (2) `AND`/`ORR`/`EOR` (immediate) with `Rd=31` silently discarded the result instead of targeting SP — unlike the register-shifted-register form, these immediate encodings (except the flag-setting `ANDS`/`TST` alias) *are* SP-capable, exactly like `ADD`/`SUB` immediate. This corrupted LuaJIT's own bytecode-PC register (`X21`) after a stack realignment (`and sp, x1, #mask`), reading unrelated stack garbage on the next SP-relative load. Fixed in both the JIT gadget and confirmed-already-correct interpreter helper. `nvim` went from ~13/15 crashing to 15/15 clean runs with both fixes (`1c0f1168`).
- **arm64/riscv64: fixed iovec ABI marshaling** for `readv`/`writev`/`preadv`/`pwritev`/`process_vm_readv` — the marshaling code only special-cased amd64 for the 64-bit `{ptr, size_t}` struct layout, falling back to the 32-bit i386 layout for every other ABI including these two 64-bit guests. This read the guest's iovec array at half its real stride, corrupting every entry past the first and any `iov_len` — the visible symptom was `strace -f` on an arm64 process showing every path/struct/array argument as empty or zeroed (`ptrace` PEEKDATA doesn't use this path, but `strace`'s `process_vm_readv` fast path does) while return values stayed correct (`c51a9737`).
- **amd64: extended the i386 spurious-GPF retry.** A stale JIT block can race a concurrent COW/mmap update on another CPU and take a host `#GP` even though the target page is validly mapped; i386 already retried once, but the check and retry loop were both explicitly gated off for amd64, so the same race crashed amd64 guests immediately. Also fixed the retry dedup key, which read the wrong (stale, 32-bit) IP field for amd64 tasks. Root-caused from a device crash in a multithreaded Rust binary under multicore (`72f2b030`).
- **riscv64**: `rdtime`/`rdcycle`/`rdinstret` (the read-only Zicntr CSRs) now alias a host monotonic-clock read instead of hitting the undefined-instruction path — Go binaries (e.g. `glow`) SIGILL'd immediately on their first clock read via `runtime.nanotime()`'s `csrrs rd, time, x0` (`5d2e185d`).
- **amd64**: `preadv2`/`pwritev2` (327/328) implemented, delegating to the existing `preadv`/`pwritev` cores through the 64-bit-safe native syscall path (`7226a0d8`).
- **Crash diagnostics**: `dump_stack()`/`dump_mem()` were i386-only, reading `cpu.esp`/`.ebp`/`.eip` unconditionally regardless of guest ABI — a page-fault dump on amd64/arm64/riscv64 printed garbage SP/FP/PC and cut short with a bogus "Unable to read memory" instead of a real stack dump. Now ABI-aware (`91cdbec5`), and crash-report `dmesg` lines are now tagged with the crashing task's guest ABI so a fault under a cross-arch chroot is unambiguous (`1a75d963`).

### Networking

- **Two `fs/sock.c` bugs fixed around lost socket errors on the macOS host.** A refused nonblocking `connect()` correctly sets `SO_ERROR` at the host level, but iSH's own internal write-readiness probe read (and thus cleared) it first, so the guest's own subsequent `getsockopt(SO_ERROR)` — the standard pattern every nonblocking network client uses — saw a false "success". Now cached on first observation and returned to the guest before being cleared (`02b1f652`). Separately, the existing `ENOTCONN`→`ECONNRESET` fixup for iOS backgrounding socket kills (`read`/`write` already had it) was missing from `recvmsg`/`recvmmsg`/`recvfrom`/`sendmsg`/`sendto` — live on-device, this made `chronyd`'s UDP-socket NTP client spin at 100% CPU forever after any background/foreground cycle, since it saw the unexpected raw `ENOTCONN` and never closed/reopened the connection (`bea236a7`).
- Fixed a false `EADDRINUSE` on `bind()`: an Apple-only preemptive conflict check (added to compensate for every guest task sharing one host process) treated any socket sharing a domain/type and overlapping local address as a conflict, without checking whether it was actually listening — since an accepted connection's local address is the same port as its listener, a live connection to a port could make a fresh `bind()` there fail even though nothing was really occupying the slot. Reproduced via `sshd`: restarting it while an SSH session stayed connected lost the IPv4 listener while IPv6 rebound fine. Fixed to only treat genuine listeners as conflicts (`6894e0ce`).

### Tools

- **ktop**: fixed the process-list row-count floor overshooting the terminal height on resize. ktop repaints in place (no full-screen clear per frame), so drawing one line too many scrolled the whole terminal up by that much on every redraw instead of clipping; the floor that caused this (forcing at least 3 list rows) is now 0.
- Diagnostics: `strace`'s `getrlimit`/`setrlimit`/`prlimit64` format strings used `%#x` for a 64-bit value, so `RLIM_INFINITY` printed as the misleadingly-finite `0xffffffff`; and `strace`'s per-line output was silently truncated to 512 bytes, discarding anything after — both found chasing an unrelated `cc1` investigation and widened to match the real per-thread buffer size (`c2bbc543`).

### App / roots

- A downloadable Devuan 6 riscv64 root added to the in-app filesystem chooser, and the CLI harness (`main.c`) gains an opt-in second fakefs mount at `/fakemnt2` (`ISH_FAKE_MNT2`) for reproducing cross-root bugs — e.g. `mv` between two `/AOK/roots`-style fakefs mounts — without needing the iOS app (`a211e82a`).
- `tools/build-devuan-minirootfs.sh` now also builds a riscv64 minirootfs by default, matching the Alpine minirootfs naming convention (`dfc6b9fc`).
- New `/AOK/docs` pages: an overview of what `/AOK` is, plus dedicated pages for benchmarks, Files-app integration, ktop, LLM Chat, `/AOK/persist`, roots/chrooting, runtime tuning knobs, and Workspace (`83630821`).

## Known Issues

- The futex `SA_RESTART` lost-wake issue remains open (deferred; real-software-immune, device-only repro; an earlier attempted fix was reverted).
- `NETLINK_AUDIT` remains unimplemented ("Failed to connect to audit daemon" from anything that probes it).
- `--sockabuse` can still hang on a second, less-understood `recvfrom` wedge distinct from the signal-mask bug fixed in an earlier release.
- **Resolved this cycle**: `tests/manual/concurrent_exec_tlb.c`'s local `waitpid: Interrupted system call` failure, previously listed here as an open investigation, is fixed — see Signals/locking above (`7103aebc`).
- `tests/manual/pidfd_clone.c`'s `pidfd readable after child exit` check is flaky under heavy sequential load (failed once during a full-suite run, passed 3/3 in isolated reruns immediately after) — a timing sensitivity in the test's 2000ms poll wait, not a fix regression. Separately, `pidfd_open`/`pidfd_send_signal` remain minimal stubs (see the maintainer notes on `amd64_syscall_coverage`), so this check's more fundamental gap (pidfd exit-readiness not wired to real process exit) is still open regardless.
- `tests/manual/ptrace_group_stop.c` showed one `FAIL timeout` during a local full-suite run (passed 3/3 in immediate isolated reruns there), and later failed on 2 of 4 architectures (amd64, riscv64) during the on-device 4-way concurrent multi-arch test while passing on the other 2 (arm64, i386) in the same run — its fixed 15-second `alarm()` looks too tight for heavy concurrent-arch load rather than a deterministic correctness bug, but not confirmed. Tracked as [emkey1/ish-AOK#478](https://github.com/emkey1/ish-AOK/issues/478).
- **New, on-device only**: i386 crashed (`#GP` fault on `lock`-prefixed atomic instructions, in glibc/pthread shared-library code) running `signalfd_epoll_deadlock` during the 4-way concurrent multi-arch device test — passed on amd64/arm64 in the same run, and this i386 run had already passed many other pthread-heavy tests, so not a static missing-gadget gap. Root cause: `kernel/mmap.c`'s `host_mem_headroom_low()` guard (a jetsam-avoidance measure — refuse all further guest `mmap()` once iOS reports under ~192MB of *app-level* memory headroom, regardless of total device RAM) was tripping with the app using only ~500MB, confirmed via the device's Wayland debug log (`shm.c:438: failed to mmap SHM backing memory file: Cannot allocate memory`) and reproduced live (closing one window freed enough headroom to open another). The guard fired completely silently before this cycle; it's now logged (rate-limited) when it trips (`89efe969`). The app also gained the `increased-memory-limit` and `extended-virtual-addressing` entitlements (`2fefc0e8`, `9db0655c`), which should raise the effective ceiling — not independently verified to fix the underlying window-count limit, since that depends on how much headroom iOS actually grants with these entitlements on a given device, which isn't something this cycle's testing could confirm. `increased-memory-limit` in particular requires the "Increased Memory Limit" capability to be enabled for `app.ish.iSH-AOK` in the Apple Developer portal (or via Xcode's Signing & Capabilities) before it takes effect — the entitlements file change alone isn't sufficient. wlroots' own "compositor is not releasing buffers immediately" warning in the same log is a separate, not-yet-investigated lead on why memory pressure builds up in the first place, worth a follow-up regardless of how much the entitlement changes help.
